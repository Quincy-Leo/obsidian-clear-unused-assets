# clear-unused-assets

[English](./README.md) | **简体中文**

粘贴的截图、剪藏的图片、随手画的示意图，会在引用它们的笔记早已删掉之后仍留在仓库里。本插件找出仓库中不再被任何笔记引用的附件并删除 —— 在动手之前先把找到的文件逐个列出来，每个都带一个勾选框，你可以取消勾选保留其中任意一个。

本插件受 oz-clear-unused-images-obsidian 启发。开发本插件是为了解决前人的一些遗留问题：
1. oz-clear-unused-images-obsidian 已经很久没有更新了，issue也没有人维护
2. oz-clear-unused-images-obsidian 不识别html引用中的链接，会误删附件
3. oz-clear-unused-images-obsidian 删除附件无二次选择机制，有时用户并不清楚自己删除了哪些附件，或无法单独删除哪些附件

针对以上问题，本插件**最重要的创新**是添加了一个二次确认列表，允许用户手动选择删除哪些内容、保留哪些内容。

本插件完全由 Claude Opus 5 开发完成。

- **最低 Obsidian 版本**：1.4.0
- **平台**：仅桌面端
- **界面语言**：简体中文 / English
- **协议**：MIT

## ✨ 判定原则

整套设计都由一条不对称推出来：**漏认一个引用会删掉你还需要的文件，而多认一个引用只是留下一个你本想删的文件。** 下面每一处都往后者的方向偏。

- 🔎 **引用扫描覆盖整个仓库**：排除目录只缩小*删除*范围；引用永远从整个仓库收集，否则被目标目录之外的笔记引用的附件会被误判为未引用
- 🧩 **两遍扫描取并集**：Obsidian 的 `metadataCache`（wiki 链接、Markdown 链接、嵌入、frontmatter 链接、canvas 节点）**加上**对每个文本类文件的原文扫描 —— 因为缓存看不见 `<img src>`、CSS 的 `url()`、`srcset`、`[ref]:` 定义、frontmatter 裸路径、YAML 列表项、`.base` 视图配置。原文扫描最后还有一条兜底规则：任何看起来像文件名的 token 都算。把用户实际会用的写法一条条枚举出来是场必败的仗，而漏掉一条的代价是删掉一个文件
- 🛑 **失败即中止**：扫描读不了或解析不了的文件会中止本次运行并报出该文件。这包括坏掉的 canvas JSON，以及以压缩 JSON 存储的 Excalidraw 画板 —— 后者的图片引用任何解析器都看不见
- 🚨 **跳闸保护**：若范围内的附件有九成以上看着都没被引用（且总数至少 10 个），直接中止，而不是提议把你的附件目录清空 —— 这种形态是冷索引的特征，不是仓库脏
- ⏳ **等索引建完**：两个入口在 Obsidian 报告链接解析完成之前一律拒绝执行
- ⚠️ **拿不准的项标出来**：同名文件冲突、名字出现在 Obsidian 的未解析链接里、或只作为一处断掉的文本引用被看到过的候选，会以**未勾选**状态列出，也就是默认保留
- 🔁 **删除前重新校验**：确认弹窗可能开着好几分钟，所以删除时会再扫一遍引用。期间变成被引用、或已被移动的文件会被保留并如实上报
- 🗂️ **文档永远不算附件**：`md`、`canvas`、`base` 即便写进扩展名也会被忽略 —— 对笔记来说 “没有被引用” 是正常状态
- 🈯 **双语 UI**：设置页可切换中/英，命令名与 ribbon 提示文本同步刷新
- 🧷 **配置安全**：`data.json` 带 `version` 字段；文件读坏时插件仍然加载但功能暂停，设置页提供修复按钮，修复前先备份旧文件

## 🚀 安装

**手动安装（当前仅此方式）**

```
<Your Vault>/.obsidian/plugins/clear-unused-assets/
├── main.js
└── manifest.json
```

1. 在你的 Vault 下创建 `.obsidian/plugins/clear-unused-assets/` 目录
2. 在仓库根目录执行 `npm install`
3. 编辑 `build.sh` 里的 `TARGET_DIR` 指向上述目录，然后运行 `./build.sh` —— 会调用 esbuild 打包并把 `main.js` / `manifest.json` 拷贝过去
4. 在 Obsidian 中启用插件

## 🖱️ 触发方式

两个入口执行的是同一件事：

- 点击左侧 Ribbon 图标（`image-file`）
- 命令面板 → `清理未被引用的附件` / `Clear unused assets`

执行结果以 Notice 反馈。已删除、已保留、失败的完整路径清单输出到开发者控制台 —— 既留下了这类破坏性操作的记录，又不会在屏幕角落堆一大片文字。

## ⚙️ 设置

路径：`设置 → 第三方插件 → clear-unused-assets`

### Language / 语言

| 取值 | 说明 |
|---|---|
| `zh-CN`（默认） | 中文界面，命令名 “清理未被引用的附件” |
| `en` | 英文界面，命令名 “Clear unused assets” |

切换后命令面板条目与 Ribbon 提示会实时更新（内部通过 `removeCommand` + `addCommand` 重新注册）。

### 清理范围

| 设置项 | 默认值 | 含义 |
|---|---|---|
| 清理目录 | *（留空）* | 相对于仓库根目录的相对路径，一行一个。留空表示整个仓库。子目录一并处理。 |
| 排除目录 | *（留空）* | 相对于仓库根目录的相对路径，一行一个。留空表示不排除。子目录一并排除。**只缩小删除范围。** |
| 要清理的扩展名 | `png,jpg,jpeg,gif,bmp,svg,webp,avif` | 英文逗号分隔，不区分大小写，可以带点。 |

两个目录列表的校验同等严格，任一有问题都会**中止运行**而不是仅作提示：

- 绝对路径（`/assets`、`C:\pics`、`~/pics`、`\\server\share`）或含 `..` 的路径一律拒绝 —— **每一行**都查，包括某个已通过目录的重复写法
- 不存在的路径，或指向文件而不是目录的路径，一律拒绝
- 清理目录整体位于某个排除目录之内时，报为配置自相矛盾，而不是静默地扫不出任何结果
- 不可能成为扩展名的写法（`png jpg`、`PNG;JPG`）会被拒绝而不是留下 —— 分隔符打错时报 “扩展名为空”，而不是看着有效却永远匹配不上

排除写错和清理写错同等对待是有意为之：清理目录写错只是找不到东西，而排除目录写错会静默地拿掉你明确要求的保护。

校验结果就地显示在字段旁边，不会每敲一个字弹一个 Notice。文本字段按约 500 毫秒防抖落盘，离开设置页时会冲刷掉未落盘的编辑。

### 删除方式

| 设置项 | 默认值 | 含义 |
|---|---|---|
| 删除到哪里 | 移到 Obsidian 回收站（`.trash`） | `跟随 Obsidian 设置`（`FileManager.trashFile`）、`.trash`、系统回收站、永久删除 |
| 删除前需要确认 | 开 | 列出候选文件，每个带勾选框 |

选择**永久删除**会强制打开确认开关并将其锁定。永久删除没有撤销；一旦无人值守地运行，引用识别的每一处缺口都会变成不可恢复的损失 —— 在多设备同步的仓库里尤其如此：还没收到某篇笔记的设备，不可能知道那篇笔记引用了哪个文件。

### 重置

把全部设置恢复为默认值并立即写入 `data.json`。排队中的文本编辑会被丢弃，避免防抖到点后又把刚清掉的值写回来。

## 🗃️ `data.json` 与 `version` 字段

配置文件带 `"version": 1`。策略是刻意严格的 —— 对读不懂的配置文件绝不猜：

**读取时**

| 盘上的 `version` | 行为 |
|---|---|
| 缺失 / 非整数 / `< 1` | 报错：字段非法。插件仍然加载。 |
| `> 1` | 报错：配置文件版本高于插件。插件仍然加载。 |
| `1` | 正常。个别非法字段各自回退默认值；本版本不认识的键原样保留。 |
| 文件存在但解析不了 | 报错：文件损坏。**绝不**会被当成新装，因此你的字节不会被覆盖。 |
| 文件不存在（新装） | 写入默认值。不算错误。 |

读失败后插件处于**已加载但暂停**状态：弹 Notice 说明原因，两个功能入口拒绝执行，设置页照常渲染出全部控件外加一个**修复配置文件**按钮。能读出来的字段会保留，所以修复是保住你的配置而不是把它清空。

**写入时**

每次写入都先重新读一遍文件，且所有写入串行排队，读—判断—写的过程不会交错：

| 盘上的 `version` | 行为 |
|---|---|
| 缺失 / 非法 / `< 1` | 先备份为 `data.<时间戳>.json.bak`，再写入合法的新文件。 |
| `> 1` | 拒绝写入，并说明原因。 |
| `1` | 写入，并叠加在盘上原文件之上，未知键得以保留。 |

只要写入发生在配置处于损坏状态时，即便盘上的文件本身能正常解析也会先备份 —— 那种状态下内存里的值是重建出来的，盘上的字节可能是真配置的唯一副本。

备份文件名带时间戳且绝不覆盖已有备份，所以第二次坏写不会毁掉第一次的备份。

拒写规则只有一个例外：用户显式点击**修复配置文件**。拒绝*自动*写入是为了保护另一个更新版本的兄弟安装的配置，但拒绝一次显式修复会让用户在插件内无路可走。

新增一个设置项**不会**提升版本号 —— 只有旧代码确实读不懂的改动才会。

## 🏗️ 项目结构

```
src/main.js          插件生命周期：命令、ribbon 图标、设置页注册、整条运行流程
src/settings.js      i18n 文案表、data.json 持久化、设置页
src/scope.js         范围校验：本次运行允许动哪些目录与扩展名
src/clear.js         扫描 + 删除引擎
src/confirmWindow.js 逐文件勾选的确认弹窗
ut/                  node:test 单元测试；ut/helpers/bootstrap.js 负责替换 `require("obsidian")`
```

各模块职责不重叠：`settings.js` 从不扫描，`scope.js` 不碰文案也不碰持久化，`clear.js` 从不弹 Notice 也不碰 DOM，`main.js` 是唯一把它们串起来并与用户交互的地方。

`resolveScope()` 放在 `scope.js`，由设置页和运行入口共用 —— 这样设置页不可能把一份运行时会被拒绝的配置显示为 “有效”。

```bash
npm install
npm test        # node --test ut/*.test.js
npm run check   # esbuild 打包后再对产物做语法检查
```

### 开销

在一个合成的两万文件仓库上（16000 篇约 2KB 的笔记 + 4000 个附件），完整扫描约需 **2.5 秒**，删除前的二次校验也差不多，堆内存不到 60MB。两处循环都每 50 个文件让出一次事件循环，Obsidian 不会卡住。

原文扫描的兜底正则锚在左侧分隔符上，以保证线性。早先没锚的版本会在一长段无分隔符的内容里从每个起始位置重扫一遍 —— 内联 base64 data URI 就是这种内容，每个未压缩的 Excalidraw 画板都含它 —— 80KB 要 4.9 秒、160KB 要 20 秒，而且全程阻塞 UI 线程。

## 🔍 引用识别的已知边界

**能识别的。** `metadataCache` 提供 wiki 链接、Markdown 链接、嵌入、frontmatter 链接，以及（1.12+）canvas 节点。在此之上，原文扫描会读**每一个不属于已知二进制格式的文件** —— 而不是只读一份固定的文本扩展名清单，因为一个没见过的扩展名可能是用户脚本、配置文件，或者写这份清单时还不存在的格式，而它们中任何一个都可能是某个附件唯一的引用来源。读出来发现含 NUL 字节的，按二进制跳过。

扫描能识别：带引号或不带引号的 `<img src>`、`xlink:href`、`data`、`poster`、`srcset`、CSS 的 `url()` 与 `image-set()`、引用式定义（`[ref]: 路径`）、脚注正文、表格单元格、callout、frontmatter 裸路径、YAML 列表项、`.base` 视图配置、canvas 的 `file` 与 `group.background` 键、Windows 反斜杠路径、百分号编码的文件名、含 `#`/`?`/`|` 的文件名、含空格的文件名（包括 Obsidian 自己的 `Pasted image …png` 默认命名），以及其余任何以扩展名结尾的、由分隔符界定的 token。

**会中止运行而不是猜的。** 读不了的文件、坏掉的 canvas JSON，以及开启了 “Compress Excalidraw JSON in Markdown” 后保存的 Excalidraw 画板 —— 压缩后的画板里嵌入图片的 wiki 链接并不以文本形式存在，任何解析器都看不见。关掉压缩，或把该附件目录加入排除。

**刻意偏向多认。** 代码块或 `%%注释%%` 里的链接在 Obsidian 里并不产生反向链接，但原文扫描仍会算上它，于是该文件被保留。这是有意为之：偏向保留的代价是留下一个你本想删的文件，偏向另一边的代价是删掉一个你需要的文件。同理，解析不出来但看着像文件名的 token 会被记下来，于是同名候选会被标上疑点而不是默认勾选。

**原理上无法知晓的。** 另一个仓库、Publish / Quartz / Hugo 构建流程、Anki 卡组、外部工具、仓库之外某处的 `obsidian://` 链接，或指向仓库之外的符号链接。`.obsidian/` 下的文件（主题片段、其他插件的 `data.json`）对 `vault.getFiles()` 不可见，也不在扫描范围内，所以只被某个 CSS 片段引用的图片是看不到的。把删除去向保持为可恢复、把确认保持为开启，就是对这类情况的兜底。
